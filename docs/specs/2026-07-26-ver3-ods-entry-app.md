# ver3・表形式入力／ODS出力仕様

## 文書情報

- 対象アプリ：出張旅費申請アプリ
- 開発仕様書版：Ver.1.0
- 採用日：2026-07-26
- 位置付け：既存ver2からver3へ移行するための変更専用仕様書

## 目的

社内出張旅費申請を、過去実績を利用した表形式入力と現行社内書式のODS出力により簡略化する。

## 変更提案（承認済み）

### 変更内容

- 主画面を、日付・目的地・区間・金額・理由を行単位で入力するPC向け表形式へ変更する。
- 入力は各項目をEnterで確定し、次の項目、次の行へ進む。
- 過去実績を候補として表示し、矢印キーとEnterで選択できるようにする。
- 出力形式を、Excel中心の出力から現行社内フォーマット固定のODS出力へ変更する。
- 保存データを設定情報、月データ、実績マスターとして整理し、ブラウザ内に保存する。
- WindowsのPCブラウザを主利用環境とし、Mac等でも確認できるPWA構成を維持する。

### 変更理由

- 毎月の定型入力を、実際の申請書に近い順序で素早く処理するため。
- 過去実績を候補として再利用しつつ、候補外の入力も妨げないため。
- 利用者が最終確認・修正・印刷にLibreOfficeを使用できるODSファイルを作るため。

### メリット

- キーボード中心で連続入力できる。
- 実績を使うほど候補精度と入力効率が上がる。
- クラウド、ログイン、外部経路APIに依存せず個人利用できる。
- 現行社内書式に合わせた出力を維持しやすい。

### デメリット

- ODS原本の実ファイルと印刷結果を使った最終調整が必要。
- 書式変更時はアプリ改修が必要。
- ブラウザの安全制約により、保存先の再利用や同名ファイルの上書き確認は対応ブラウザの機能差を受ける。
- 既存ver1／ver2画面とデータからの移行処理が必要。

## 変更内容

### 1. 開発方式と利用範囲

- PWA（Webアプリ）として実装する。
- PCブラウザ、主にWindows環境で利用する。
- Mac等でも確認可能な構成とする。
- 個人利用を前提とし、ログイン、クラウド同期、複数端末同期は実装しない。

### 2. データ保存

- ブラウザ内保存を使用する。実装方式はIndexedDBを基本とする。
- 設定情報として、所属、氏名、定期区間情報を保存する。
- 定期区間は情報保持のみとし、旅費判定には使用しない。
- 月単位で、日付、目的地、区間、金額、理由を保存する。
- 実績マスターとして、目的地、区間、金額、理由、使用回数、最終利用日を保存する。

### 3. メイン画面

- 表示列は「日付、目的地、区間、金額、理由」とする。
- 1項目ごとにEnterで確定し、日付 → 目的地 → 区間 → 金額 → 理由 → 次行の日付の順に進む。
- 対象月を選択し、日付欄には日だけを入力できる。
- 次行の日付欄には直前行の日付を初期表示する。
- 空白行と金額0円の行は出力対象外とする。

### 4. 候補入力

- 過去実績を入力候補として利用する。
- 候補が1件の場合も候補を表示し、Enterで確定できる。
- 複数候補は矢印キーで選択し、Enterで確定する。
- 候補がない場合は通常入力として扱い、入力を制限しない。

### 5. 実績マスター更新

- 1行の入力が完了した時点で実績マスターを更新する。
- 目的地、区間、金額、理由が完全一致する場合は、使用回数を1増やし、最終利用日を更新する。
- 既存候補から内容を変更した場合は、新しい実績として登録する。
- マスター登録には、最低限、目的地と区間を必要とする。

### 6. 設定画面

- 基本情報：所属、氏名、定期区間情報。
- 過去申請書取り込み。
- 実績マスター管理。
- データ移行。
- 実績マスター管理では、目的地、区間、金額、理由、使用回数、最終利用日を表示し、編集・削除できる。

### 7. 過去申請書取り込み

- ODSを読み込み、明細を解析して実績マスターを更新する。
- 日付、目的地、区間、金額、理由が完全一致する明細は重複追加しない。
- 取り込みに必要な実際のODSセル配置は、現行原本を確認して確定する。

### 8. ODS出力

- 現行社内フォーマット固定とし、利用者によるテンプレート変更機能は実装しない。
- 書式変更時はアプリ改修で対応する。
- 固定原本は `2026年度版出張旅費代精算書原本（エクセル入力）.ods` とする。
- 使用シートは `【原本】出張旅費精算` とし、`【見本】出張旅費精算` は出力しない。
- 原本のシートをページ数分複製し、書式、罫線、結合セル、注意書き、印刷設定を維持したまま値だけを設定する。
- 日付の月・日、目的地、区間、金額、理由を出力する。
- 月と日は数字として出力する。
- 明細は11～30行とし、A列へ月、B列へ日、C列へ目的地、D:E結合セルへ区間、F列へ金額、G:H結合セルへ理由を出力する。
- 所属はC1:D1結合セル、氏名はA5:D5結合セル、月度見出しはA3:H3結合セル、ページ番号はG1:H1結合セルへ出力する。
- 合計欄はF31とし、各シートで `SUM(F11:F30)` を使用する。
- 明細を20件ごとに分割し、ページ番号を自動入力する。
- 合計金額はアプリで固定値を書かず、ODS計算式を利用する。
- 出力シート名は `出張旅費精算_1` から始め、20件ごとに連番を増やす。
- 原本の印刷設定（A4縦、上下余白0.762cm、左右余白1.778cm、66%縮小）を維持する。
- ファイル名は `YYYYMM_出張旅費精算書.ods` とする。
- ODSはブラウザ標準のダウンロード機能で保存する。
- 保存先の再利用と同名ファイルの上書き確認は、ブラウザ制約と対応状況を踏まえた将来の検討事項とし、ver3の公開必須条件には含めない。
- ODS作成後の確認、修正、印刷はLibreOfficeで行う。

## 変更しない範囲

- クラウドサービス、ログイン、複数端末同期は追加しない。
- 定期区間情報を旅費額の自動判定には使用しない。
- 外部経路検索や外部AIへ申請データを送信しない。
- ODS作成後の確認、修正、印刷はアプリ内で行わない。
- 既存の保存データを利用者の許可なく削除しない。

## 実装計画・作業項目

### Phase 1：基本入力

1. ver3データ形式と既存データ移行を実装する。
2. 対象月と表形式入力画面を実装する。
3. Enter移動、日だけの入力、前回日付の引継ぎを実装する。
4. 月データのブラウザ内保存を実装する。

### Phase 2：実績活用

1. 入力候補、矢印キー選択、Enter確定を実装する。
2. 行完成時の実績マスター更新を実装する。
3. 実績マスターの編集・削除を実装する。
4. ODS過去申請書の読み込みと重複除外を実装する。

### Phase 3：ODS出力

1. 現行ODS原本のシート、セル、数式、印刷範囲を確認する。
2. 固定書式への明細出力を実装する。
3. 20件単位のページ分割、ページ番号、合計式を実装する。
4. ファイル名、保存先、同名ファイル確認を実装する。
5. LibreOfficeで表示・数式・印刷結果を確認する。

### Phase 4：補助機能

1. 設定画面とデータ移行を整備する。
2. Windowsでのキーボード操作と保存操作を確認する。
3. UIとアクセシビリティを改善する。

## 未決事項・必要資料

- 過去ODS申請書の実ファイルによる読み込み確認。
- 保存先再利用、同名ファイル上書き確認、File System Access API採用の要否。
- 既存ver1／ver2の詳細機能をver3画面に残す範囲。
- Windows版LibreOfficeでのMSゴシック、文字切れ、罫線、結合セル、印刷プレビューの実機確認。

## 完了条件

- 対象月を選び、日付、目的地、区間、金額、理由をEnter中心で連続入力できる。
- 入力内容が月単位でブラウザ内に保存される。
- 過去実績候補をキーボードで選択でき、候補外も自由入力できる。
- 行完成時に実績マスターが仕様どおり更新される。
- 実績マスターを表示、編集、削除できる。
- 過去ODS申請書を読み込み、重複を除いて実績マスターへ反映できる。
- 空白行と0円行を除き、20件単位で現行書式のODSを作成できる。
- ODSのファイル名、ページ番号、合計式が仕様どおりである。
- LibreOfficeで確認、修正、印刷できる。
- 対象機能のテストとビルドが完了し、既存データが失われない。

## 実装結果

- 2026-07-26にver3の初期実装を実施。
- 既存のIndexedDB保存とver1／ver2データを維持したまま、表形式入力を既定画面として追加。
- 日、目的地、区間、金額、理由のEnter移動、目的地候補、候補選択時の区間・金額・理由補完、次行への日付引継ぎを実装。
- 行完成時の月データ保存、実績マスターの完全一致集約、使用回数・最終利用日更新を実装。
- 実績マスターの一覧、編集、削除を実装。
- ODS・XLSX・CSV・TSVの過去申請書取り込み導線を実装。ODSは内部の表データを端末内で解析する。
- 空白行と0円行を除外し、20件単位で複数シートを作成するODS出力を実装。
- ODS内に所属、氏名、ページ番号、明細、シート単位の合計計算式を出力し、ファイル名を `YYYYMM_出張旅費精算書.ods` とした。
- 機能テスト15件、公開物テスト2件、TypeScript型チェック、公開用ビルドに成功。
- 2026-07-26に現行社内ODS原本対応を実装。固定原本をアプリへ同梱し、`【原本】出張旅費精算` シートを20件単位で複製して値だけを書き換える方式へ変更。
- 原本のセル位置、結合セル、罫線、文字スタイル、注意書き、A4縦・指定余白・66%縮小の印刷設定を維持する。
- 21件の検証データで2シートを生成し、LibreOfficeで修復警告なく開けること、PDF変換時にA4縦2ページとなることを確認。
- 1ページ目20件・F31合計3,980円、2ページ目1件・F31合計199円となり、各シートの `SUM(F11:F30)` が正しく動作することを確認。
- 出力ODSと原本の `styles.xml`、`settings.xml`、`META-INF/manifest.xml` が同一であることをSHA-256で確認。
- 検証環境に原本指定のMSゴシックがないため、PDF上の日本語字形表示は確認できなかった。セル内の日本語文字列と配置はXMLで確認済み。Windows／LibreOfficeでの最終字形・印刷プレビュー確認は継続。
- 保存フォルダ再利用、同名ファイル上書き確認は未実施。
- ODS原本対応の実装commitは `0a519e0`。GitHubの `main` へpush済み。Sites Version 7を「Ver3実運用テスト版」として本番公開済み。
- 2026-07-26：Version 7は公開せず保留。保存先再利用と同名ファイル上書き確認はブラウザ制約を踏まえた検討事項とし、Windows版LibreOfficeでの表示・印刷確認を公開判断の優先条件とする。
